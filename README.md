# 3x-ui Panel — Railway Deployment 🚀

دیپلوی پنل **3x-ui** (نسخه‌ی رسمی و آخرین ریلیز — در حال حاضر **v3.8.5**) روی **Railway** با استفاده از ایمیج رسمی `ghcr.io/mhsanaei/3x-ui:latest`.

این ریپو هیچ کدی از 3x-ui را کپی نمی‌کند؛ ایمیج **رسمی** پروژه در [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui) مستقیماً کشیده می‌شود، بنابراین همیشه **آخرین نسخه‌ی رسمی** اجرا می‌شود.

---

## ✨ چه چیزهایی تنظیم شده؟

| فایل | توضیح |
|---|---|
| `Dockerfile` | بر پایه‌ی ایمیج رسمی 3x-ui (تگ `latest`)؛ fail2ban غیرفعال (Railway قابلیت `NET_ADMIN` نمی‌دهد) و اسکریپت استارت اضافه شده |
| `start.sh` | پورت پنل را هنگام بوت با پورت تخصیص‌یافته‌ی Railway (`$PORT`) هماهنگ می‌کند و دیتابیس را مقداردهی اولیه می‌کند |
| `railway.json` | بیلدر Dockerfile و سیاست ری‌استارت خودکار |

- منطقه‌ی زمانی پیش‌فرض ایمیج رسمی: `Asia/Tehran` ✅
- پورت پیش‌فرض پنل: `2053` (به‌صورت خودکار با `$PORT` هماهنگ می‌شود)

---

## 🚀 راه‌اندازی روی Railway

### مرحله ۱ — اتصال ریپازیتوری
1. وارد [Railway](https://railway.app) شوید (با GitHub لاگین کنید).
2. **New Project → Deploy from GitHub repo** را بزنید.
3. ریپازیتوری `3x-ui` را انتخاب کنید.
4. Railway خودکار `Dockerfile` را تشخیص می‌دهد و بیلد می‌گیرد.

> نکته: Railway از ریپوی خصوصی/عمومی شما بیلد می‌گیرد؛ نیازی به تنظیم اضافه‌ای نیست.

### مرحله ۲ — دامنه و پورت
1. بعد از دیپلوی موفق، به تب **Settings → Networking** سرویس بروید.
2. **Generate Domain** بزنید.
3. اگر Railway پورت هدف را نپرسید یا پورت اشتباه تشخیص داد، **Target Port** را دستی روی `2053` بگذارید (اسکریپت استارت در هر صورت خودش را با `$PORT` هماهنگ می‌کند).

### مرحله ۳ — ورود به پنل
- آدرس: `https://<دامنه-شما>/`
- نام کاربری: `admin`
- رمز عبور: `admin`

> ⚠️ **فوراً بعد از اولین ورود، از منوی Panel Settings نام کاربری، رمز عبور و Base Path را عوض کنید.** آدرس پنل بعد از تغییر Base Path به شکل `https://<دامنه>/<base-path>/` درمی‌آید.

## 💾 ذخیره‌سازی دائمی (اختیاری ولی توصیه‌شده)

بدون Volume، با هر دیپلوی مجدد، تنظیمات و اینباندها پاک می‌شوند (فایل‌سیستم موقتی است):

1. در سرویس، تب **Settings → Volumes** را باز کنید.
2. یک Volume بسازید و Mount Path را روی `/etc/x-ui` بگذارید.
3. سرویس را ری‌دیپلوی کنید.

---

## 🔄 به‌روزرسانی به آخرین نسخه

چون ایمیج برچسب `latest` را کش می‌کند:

1. در Railway، سرویس را باز کنید.
2. **Deploy → Redeploy** (یا در تب Deployments گزینه‌ی Redeploy) را بزنید.
3. Railway ایمیج را دوباره می‌کشد و آخرین ریلیز رسمی 3x-ui اجرا می‌شود.

اگر Volume بسته باشید، دیتابیس و اینباندها در به‌روزرسانی حفظ می‌شوند.

---

## 🌐 نکته‌ی اینباندها روی Railway

Railway ترافیک HTTP/HTTPS و WebSocket را روی دامنه‌ی سرویس پشتیبانی می‌کند:

- **پیشنهادی:** پروتکل‌های `VLESS` / `VMess` / `Trojan` با ترنسپورت `WS` یا `gRPC` + TLS (از Cloudflare یا TLS خود Railway).
- اینباند پنل روی همان پورت عمومی سرویس کار می‌کند؛ برای اینباندهای دیگر می‌توانید در Settings → Networking دامنه‌های اضافه با Target Portهای دیگر بسازید یا از **TCP Proxy** استفاده کنید.

## 🔧 متغیرهای محیطی (اختیاری)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | توسط Railway ست می‌شود | پورت پنل؛ اگر ست نشود `2053` |
| `XUI_DB_TYPE` | `sqlite` | امکان `postgres` (DSN لازم دارد) |
| `XUI_DB_DSN` | — | رشته‌ی اتصال PostgreSQL وقتی `XUI_DB_TYPE=postgres` است |
